# 6. Инфраструктура и масштабируемость решения

Вес критерия — 0.10. Честная самооценка — 4/5 (см. пробел ниже).
Полное обоснование — `../../alert-platform/COMPLIANCE_MATRIX.md`,
раздел 6, и `../../alert-platform/INFRASTRUCTURE.md`.

| Требование | Реализация | Доказательство | Тест | Пробел |
|---|---|---|---|---|
| Отказоустойчивость (резервирование, недопущение потери событий) | WORM + идемпотентность + `FOR UPDATE SKIP LOCKED` + async streaming-реплика PostgreSQL + ежедневный `pg_dump` | `INFRASTRUCTURE.md` §2 | Replay_lag ~0,25с; ClickHouse OOM найден и исправлен | нет по основному пути; частный случай ClickHouse (побочный контур) — исправлен |
| Определены обособленные ресурсы для ИИ-модуля | Технически изолировано — Go/Python используют один HTTP-контракт (`OLLAMA_URL`); фактическое GPU разделяется со стендом | `INFRASTRUCTURE.md` §4 | Единственная модель `log-reader` (30B) занимает 90% VRAM | **Честный пробел**: выделенных ресурсов нет, только программная изоляция — разница между 4 и 5 |
| Мониторинг и аналитика платформы | `/console/app` — нагрузка очереди, % разбора, % доставки, MTTR, задержка | `INFRASTRUCTURE.md` §5 | Дашборд поймал аномалию отрицательного MTTR из смешения тестовых сессий | нет |
