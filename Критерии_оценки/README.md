# Критерии оценки — навигация для проверяющих

Эта папка — точка входа для жюри. Восемь подпапок ниже соответствуют
восьми критериям официальной таблицы оценки кейса (`КЕЙС_студенты_ITCamp.pdf`,
стр. 6–7); в каждой — короткий README с тем, что именно реализовано,
где это в коде и как это проверить самостоятельно за несколько минут.
Полная построчная версия с проверяемыми фактами — `../alert-platform/COMPLIANCE_MATRIX.md`
(эта папка — навигационная витрина над ним и над `../alert-platform/PRESENTATION_CONTENT.md`,
не замена: код и данные никуда не переносились, только добавлены README-указатели).
Полная техническая документация (архитектура, карта модулей, доменная
модель, ADP AI, тестирование) — `../alert-platform/DOCUMENTATION.md`.

## Быстрый доступ к живому стенду

Платформа уже развёрнута и работает — не нужно ничего запускать, чтобы
посмотреть:

**https://газвпол.рус/console/app/**

## Тестовый доступ

| Логин | Пароль | Права |
|---|---|---|
| `тестер1` (кириллица, не `tester1`) | `000000` | Демо-аккаунт с урезанными правами — специально для показа RBAC. Есть: главная, алерты, инциденты, оборудование, сотрудники, покрытие, сценарии (просмотр), аналитика, ADP AI, справка. Нет: редактирование SLA/сценариев/источников/пользователей/интеграций — эти действия должны заканчиваться `403 Forbidden`. |
| `admin1` | `admin123` | Администратор платформы — полный доступ, для сравнения с урезанными правами `тестер1`. |

Полный список тестовых учётных записей (LDAP) — `../alert-platform/USER_GUIDE.md`,
раздел «Приложение: демо-доступы».

## Живой демо-сценарий (воспроизводим за 5 минут)

1. Войти как `тестер1`.
2. Открыть **ADP AI** → спросить «Покажи активные критические инциденты» — реальный ответ по данным БД, не заготовка.
3. Спросить «Кто сейчас доступен для реакции на инцидент N?» (N — любой открытый инцидент из раздела «Инциденты») — реальная доступность сотрудников.
4. Открыть вкладку **Журнал** в ADP AI — видно `SUCCESS` по обоим запросам.
5. Попробовать изменить правило SLA (раздел **SLA**) — будет `403`, у `тестер1` нет `sla.manage`.
6. Войти как `admin1` → **Администрирование → Пользователи и права** → найти `тестер1` → выдать `sla.manage`.
7. Войти обратно как `тестер1` → то же самое изменение SLA теперь проходит.

Это тот же живой цикл «отказ → выдача права → повтор», который описан
в `../alert-platform/COMPLIANCE_MATRIX.md` и был лично проверен вживую
на проде при разработке (не только в теории).

## Запуск локально (воспроизводимость, не обязательно для быстрого просмотра)

Живой стенд выше достаточен для оценки, но платформа полностью
воспроизводима локально — раздел «Воспроизводимый запуск» в
`../alert-platform/README.md`. Короткая версия:

```bash
cd alert-platform
cp .env.example .env
docker compose up -d --build \
  postgres postgres-replica ldap \
  migrate kb-index \
  gateway pipeline-worker delivery-planner admin-console demo-runner \
  deprovision-worker redpanda clickhouse clickhouse-migrate minio changelog-worker \
  delivery-email mailhog

python3 scripts/seed_employees.py --url http://127.0.0.1:8090 --username admin1 --password admin123
python3 scripts/seed_demo_scenarios.py --url http://127.0.0.1:8090 --username admin1 --password admin123 --activate

curl http://127.0.0.1:8081/api/v1/health   # ожидается 200
open http://127.0.0.1:8090/
```

`TrueConf`-доставка требует реальных `TRUECONF_*` в `.env` (без них
`delivery-trueconf` осознанно не поднимается — см. `../alert-platform/README.md`);
весь остальной домен (приём событий, разбор, корреляция, маршрутизация,
ADP AI, консоль) работает и проверяется без него.
